# Community

Choose where to ask for help, report an issue, contribute, or share a reproducible scenario.

<a name="feedback"></a>

## Contact and feedback

| What to do | Where to go | What to include |
| --- | --- | --- |
| Ask a question or report a bug | [GitHub Issues](https://github.com/datagallery-lab/datafoundry/issues) | Version or commit, environment, expected and actual results, reproduction steps, and any relevant redacted logs or traces |
| Suggest a feature or data source | [GitHub Issues](https://github.com/datagallery-lab/datafoundry/issues) | User role, workflow, data involved, current behavior, and expected result |
| Share a reproducible scenario | [Submit a scenario](scenario-cases.md) | Shareable inputs, steps, and a verifiable result |

Search for existing reports first. Note whether you can reproduce the issue on `main` when applicable. Published notices are on [GitHub Security Advisories](https://github.com/datagallery-lab/datafoundry/security/advisories).

<a name="contributing"></a>

## Contributing

For changes to docs, code, connectors, or tests, follow the [repository contribution guide](../../../CONTRIBUTING.md). See the [developer docs](../../development/index.md) for setting up the checkout and choosing tests.

<a name="sharing-materials"></a>

## Sharing materials

- Distinguish implemented behavior, experiments, and proposals. Include the version others can verify.
- Provide material that maintainers can reproduce independently. Redact logs and screenshots, and use a small synthetic dataset if needed.
- Keep credentials, customer records, proprietary data, private traces, and unpublished vulnerability details out of public reports.
