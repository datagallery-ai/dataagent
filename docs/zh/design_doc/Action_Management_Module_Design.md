## action 管理模块设计文档

### 1. 概述

#### 1.1 功能描述

action 管理模块是 DataAgent 的 **action space 网关**，负责统一管理所有可被 Agent 调用的**本地函数工具**（Action/Tool）。

模块对上层的 Planner、Executor 等组件屏蔽工具注册与调用细节，提供统一的 **注册 / 调用 / 查询** 接口。上层只需关心"工具能做什么"，而不必关心工具如何被包装与校验。

---

### 2. 设计描述

#### 2.1 设计思路

**Per-Agent 隔离**

每个 Agent 实例拥有独立的工具管理上下文。不同 Agent 之间的工具集合与 Schema 缓存完全隔离，互不污染。

**统一工具抽象**

本地函数在注册后被包装为统一的工具抽象实例。该抽象定义了调用接口、Schema 获取、参数校验、以及与 LangChain 生态的互操作能力。

**Schema 与元数据驱动**

每个工具在注册时会生成一份结构化的 Schema 描述，包含工具名、参数列表（名称、类型、是否必填、默认值）、工具描述等。通过 Schema，模块可以：

- 为 LLM function calling 生成 OpenAI 兼容的工具定义；
- 在调用前进行参数校验。

**配置驱动与解耦**

工具管理模块的初始化由 Agent 配置文件驱动。配置文件声明本地函数列表后，模块解析配置并完成注册。上层只需维护 YAML 中的工具配置段，Flex 运行时在构建 Agent 环境时会自动初始化 action space。

---

#### 2.2 模块结构

##### 2.2.1 核心组件与职责

- **工具管理器（Per-Agent 入口）**
  - 作为每个 Agent 实例的工具操作入口，负责：
    - 维护当前 Agent 的工具实例缓存与 Schema 缓存；
    - 持有本地工具注册表的引用；
    - 执行配置驱动的初始化；
    - 对外暴露统一调用接口（同步/异步）和查询接口（工具列表、Schema 获取、LLM 工具定义等）。

- **统一工具抽象**
  - 定义所有工具实例必须遵循的契约：调用执行、Schema 暴露、LangChain 兼容转换、参数校验。

- **本地工具包装器**
  - 将普通 Python 可调用对象（函数）包装为统一工具抽象，自动从函数签名和类型标注生成参数 Schema。

- **本地工具注册表**
  - 管理工具名到工具实例的映射，支持注册、注销、按分类查询。

##### 2.2.2 关键数据结构

- **工具实例缓存**：`工具名 → 工具实例` 的映射。本地工具 Key 为 `"tool_name"`（如 `"bash"`、`"read_file"`）。
- **工具 Schema 缓存**：`工具名 → Schema` 的映射。所有查询操作基于此缓存，避免重复生成 Schema。
- **工具类型枚举**：当前主线为 `本地函数` 与 `自定义`。

---

#### 2.3 关键流程

##### 2.3.1 本地工具注册流程

1. Agent 配置文件的工具段中声明本地函数工具，指定模块路径、函数名等；
2. 初始化时，模块根据配置动态导入指定模块中的可调用对象；
3. 若为普通可调用对象，则由本地工具包装器封装为统一工具抽象；若本身已是工具抽象的子类，则直接实例化；
4. 包装后的工具实例写入本地工具注册表，同时生成 Schema 并写入缓存。

##### 2.3.2 配置驱动初始化流程

1. DataAgent 构建时读取并合并配置；
2. Flex 运行时构建 Agent 环境时，为每个 Agent 创建独立的工具管理器实例，并传入其配置段进行初始化：
   - 解析**本地函数列表**：逐个导入模块与函数，依次注册；
   - 解析**内置工具**（若启用）：注册预设的常用本地工具（如文件读写、命令执行等）。

##### 2.3.3 工具调用与查询流程

- **调用**：
  - 通过工具名获取工具实例；
  - 调用工具实例的执行方法，传入参数；
  - 若为异步调用且工具支持异步，走异步路径；否则回退到同步执行（在线程池中运行）；
  - 返回统一的结果结构（含成功标志、数据、错误信息、错误类型及重试策略）。

- **查询**：
  - **按条件列出工具**：支持按分类、工具类型过滤；
  - **获取 Schema**：从缓存中返回指定工具的完整参数 Schema；
  - **获取 LLM 工具定义**：将指定工具的 Schema 批量转换为 OpenAI function calling 格式；
  - **获取工具详情/汇总**：用于诊断与管理界面展示。

##### 2.3.4 错误处理与重试

- 工具执行异常被统一分类（参数校验错误、超时、内部错误等），并关联预设的重试策略（是否可重试、最大重试次数、退避方式）；
- 调用失败时抛出统一的工具异常，上层可通过异常携带的错误类型和重试标记决定是否重试。

---

### 3. 规格约束

1. **工具命名规范**
   - 本地工具名称在单个 Agent 的工具管理器实例内必须唯一。

2. **线程安全与生命周期**
   - 每个 Agent 的工具管理器实例在 Agent 的完整生命周期内持有工具注册表；
   - 工具的注册通常在 Agent 启动阶段完成，避免运行中并发修改；
   - 资源清理（清空缓存）在 Agent 销毁时触发。

3. **异常处理**
   - 未找到工具或 Schema 时统一抛出工具异常，由上层统一处理。

4. **配置兼容性**
   - 工具管理器支持多版本的配置格式，对老版本的配置字段保持向后兼容；
   - 配置文件中的工具声明建议显式指定工具名称，避免与函数名变更耦合。
