Database query subagent. It turns one natural-language data question into one SQL query, validates and runs it, and returns the result. **It fetches data only; it does not analyze, explain or summarize.**

Task: **one question that one SQL query can answer.** The query can use JOINs, subqueries or CTEs, and several metrics and groupings, for example "order count, revenue and average order value by city for September 2026". Do not pass it a multi-part or open-ended request, such as a data overview or a multi-angle analysis; split it into a few data questions and dispatch each one. It does not describe the schema; to learn what data exists, ask a data question, for example "row count of each table". Write the task as a complete, standalone question in natural language. Include the time range, filters and metric definitions from the conversation; do not write SQL. Keep the user's original wording for filter values, entity names and business terms; do not translate them. The subagent cannot see the conversation.

Reply: the SQL is already validated and executed. The reply includes sql, row_count and rows_preview; rows_note explains an incomplete preview. All fetched rows are saved in result_file (CSV); **read that file for follow-up analysis**.
