# SQL 审核 Skill

> **前置要求**：执行本 skill 前，必须先确认已阅读并遵守 instructions.md 中的通用规则，本 skill 不重复上述内容。

## 何时使用

- SQL 执行报错，需要定位问题
- SQL 产出结果不正确，需要排查逻辑问题
- SQL 违反生产规范，需要审核合规性
- 用户明确要求"审核"、"检查"、"诊断"

## 工作流

默认仅执行 Step 1-3，直接输出审核结果。仅当用户明确要求修复时，执行 Step 4 生成修改后的 SQL。

### Step 1: 知识检索

- 通过 `read_file` 读取 sql_rules skill 中对应的知识、规则和约束，确认违规点
- 使用 `get_table_schema` 工具查询相关的元数据，验证涉及的表名、列名是否存在
- 使用 `search_udf_function_by_dsl` 或 `search_udf_function_by_name_keyword` 工具验证 UDF 函数使用是否正确
- 使用 `get_join_relations` 工具辅助判断 JOIN 写法是否正确
- 不要使用 `metadata_recall` 工具查询表、列等元数据信息

### Step 2: 问题诊断

- **语法错误**：SQL 语法不符合 Hive/Spark 方言
- **逻辑错误**：JOIN 条件、聚合粒度、过滤条件等导致结果不正确
- **规范违规**：违反 sql_rules 中的硬规则（如缺少 PARTITIONED BY、INSERT INTO 等）
- **元数据错误**：使用了错误或不存在的表、列等，UDF 函数使用错误

### Step 3: 输出审核结果

直接在回复中输出审核结果，不需要写入文件。格式如下：

```markdown
## 审核概览
- 原始 SQL：{文件路径}
- 发现问题数：严重 {X}，一般 {Y}，建议 {Z}

## 问题清单

| # | 严重等级 | 问题类型 | 问题描述 | 原因分析 | 修改建议 | 涉及位置 |
|---|----------|----------|----------|----------|----------|----------|
| 1 | 严重/一般/建议 | 语法错误/逻辑错误/规范违规/性能问题 | 具体描述 | 根因说明 | 建议的修改方式 | 文件名:行号或SQL片段 |
```

相同问题合并输出，仅需在"涉及位置"中列出所有问题位置。
违反 SQL 规范的，需在"原因分析"中列出具体规则点。

### Step 4: 修复并交付（仅当用户明确要求时执行）

- 根据审核结果中的修改建议逐项修复 SQL
- 修复后对照 sql_rules skill 中的规则重新检查，确保未引入新问题
- 涉及表名列名时必须用 `get_table_schema` 验证
- 使用 `write_file` 写入修改后的 SQL 文件（命名规则见 instructions.md）
- 调用 `validate_deliverables` 校验
