# 新建目标表名与列名的词根校验

在开始编写目标表 DDL 之前，先完成以下步骤。顺序为：先确定表名，再确定全部列名，两者都通过词根校验后才编写 DDL，随后生成 INSERT。

## 一、表名词根校验

1. 根据任务的业务含义构造完整候选表名，调用 `validate_table_word_roots` 工具校验表名。
2. 对未命中词根，结合业务含义和 `candidates` 中的中文名、描述及相关度选择合适候选做替换。修改后将完整表名再次提交 `validate_table_word_roots`，确认通过后才用于 DDL。
3. 没有合适候选时，可增大 `k` 后重新提交完整表名；仍无法确定时，向用户说明未解决的词根并请求确认，不要把未命中的词根描述为已通过校验。用户明确指定的目标表名需要修改时，应先向用户说明并确认。
4. 参数错误时，先修正输入再调用工具。如果工具不可用、调用报错或 `error_msg` 表示接口调用或返回结果异常，按词根服务不可用降级：保留候选表名继续任务，在最终交付中说明未完成校验的词根，不得声称表名已通过词根校验。已有生产表的名称不得自动修改。

## 二、列名词根校验

5. 表名通过后，收集本次 DDL 计划输出的全部列名，一次性传入 `validate_column_word_roots` 的 `columns` 校验。列名为裸标识符，使用小写字母、数字和下划线，以字母开头。
6. 返回的 `columns` 按列给出各自的 `pass` 与 `failed_roots`。对任一未命中词根的列，参照表名的做法，结合业务含义和 `candidates` 选择合适候选替换该列名；修改后将全部列名再次提交 `validate_column_word_roots`，直到整体 `pass` 为真。
7. 降级规则与表名一致：没有合适候选时可增大 `k` 重试；仍无法确定时向用户说明未解决的词根并请求确认，不得谎称已通过。工具不可用、报错或 `error_msg` 非空（含词根字典缺失导致的跳过）时按词根服务不可用降级，保留候选列名继续任务并在交付中说明，不得声称列名已通过词根校验。已有生产表的已存在列名不得自动修改。

## 三、确定后的一致性

8. 表名与列名全部确定后，DDL、INSERT、相关工具调用及交付文件名都使用相同的 `{db}.{table_name}` 和列名；如果后续表名或任一列名发生变化，先重新校验变化后的表名或完整列名，再同步更新所有相关内容。
