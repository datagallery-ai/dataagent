# 新建目标表名的词根校验

在开始编写目标表 DDL 之前，先完成以下步骤，确定每张新建目标表的表名。确定表名后再编写 DDL，随后生成 INSERT：

1. 根据任务的业务含义构造完整候选表名，调用 `validate_table_word_roots` 工具校验表名。
2. 对未命中词根，结合业务含义和 `candidates` 中的中文名、描述及相关度选择合适候选做替换。修改后将完整表名再次提交 `validate_table_word_roots`，确认通过后才用于 DDL。
3. 没有合适候选时，可增大 `k` 后重新提交完整表名；仍无法确定时，向用户说明未解决的词根并请求确认，不要把未命中的词根描述为已通过校验。用户明确指定的目标表名需要修改时，应先向用户说明并确认。
4. 参数错误时，先修正输入再调用工具。如果工具不可用、调用报错或 `error_msg` 表示接口调用或返回结果异常，按词根服务不可用降级：保留候选表名继续任务，在最终交付中说明未完成校验的词根，不得声称表名已通过词根校验。已有生产表的名称不得自动修改。
5. 表名确定后，DDL、INSERT、相关工具调用及交付文件名都使用相同的 `{db}.{table_name}`；如果后续表名发生变化，先重新校验完整表名，再同步更新所有相关内容。
