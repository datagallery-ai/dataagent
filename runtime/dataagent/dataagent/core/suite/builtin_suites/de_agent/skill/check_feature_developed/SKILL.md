# 检查特征是否已开发

只做存在性核查，不写 DDL/DML。查完给出结论，是否继续开发由用户决定。

## 工作流

1. **解析需求**：提取特征语义（主体/行为/时间窗口/粒度/指标含义）。需求模糊时先向用户确认，再检索。
2. **检索证据**（均用 `metadata_recall`，单次整合调用优先）：
   - 表/列：是否已有同名或同义特征字段、落表位置
   - 指标实例：是否已有可复用指标（主体、窗口、口径）
   - 历史 SQL：是否已有相似产出 SQL（作旁证，不作唯一结论）
3. **对照基础表**（可选）：用户指向基础特征域时，用 `read_file` 读 `add_columns/references/base_feature_tables.md` 缩小候选；实际存在性以元数据为准。用户给出明确 `{db}.{table}` 时，可用 `check_table_existence` 核对 schema。
4. **裁决**：
   - **已开发**：命中同口径表/列/指标 → 给出表名、字段、口径摘要、复用建议
   - **部分命中**：主体/窗口/口径仅部分一致 → 列出差异，询问是否复用或新建
   - **未开发**：无可靠命中 → 明确说明，询问是否走 `feature_engineering` / `add_columns`

## 输出格式

```markdown
## 核查结论：已开发 | 部分命中 | 未开发

| 特征 | 命中对象(表.列/指标) | 匹配度 | 口径差异 | 建议 |
|------|----------------------|--------|----------|------|
| ...  | ...                  | 高/中/低 | ...    | 复用/加列/新建 |

证据来源：metadata_recall / check_table_existence / base_feature_tables（按实际勾选）
```

## 约束

- 禁止凭字段名臆断“已存在”；无元数据证据不得判为已开发。
- 禁止在本 skill 内生成或修改生产 SQL。
- 历史 SQL 仅作旁证；与元数据冲突时以元数据为准。
